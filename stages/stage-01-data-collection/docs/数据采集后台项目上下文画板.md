# 数据采集后台项目上下文画板

## 一、这个项目是什么
这是一个本科毕业设计中的**数据采集子系统原型**，背景属于 **NILM（非侵入式负荷监测）智能家庭能耗分析与优化系统**。

整个毕设不是单纯做一个通信程序，也不是单纯做一个界面，而是要完成一条较完整的数据链路：

- 家庭电力采集终端产生量测数据
- 终端通过既定 TCP 协议向后台上报
- 后台接收、解析、区分终端、展示数据
- 后续再将数据用于数据集构建、清洗、分析和模型使用

因此，这个后台软件的定位是：

> **面向毕业设计数据采集阶段的“终端接入、协议解析、实时展示、设备管理”原型系统**

它既是一个工程原型，也是汇报展示材料。

---

## 二、为什么要做这个后台
在这个毕设中，数据采集不是“拿到一些数据文件”就够了，而是要证明：

1. 真实终端能够持续上报数据
2. 平台能够持续接收数据
3. 数据能够按设备区分和组织
4. 协议能够被正确解析
5. 接收到的数据能够被观察、核验、记录
6. 这条链路能为后续数据集构建服务

因此，这个后台的意义不只是“收包”，而是：

- 打通真实采集链路
- 建立数据入口
- 提供过程可见性
- 提供协议验证能力
- 为后续数据集构建提供基础支撑

---

## 三、这个原型当前关注什么，不关注什么

### 当前重点
1. 多终端接入
2. TCP 收包
3. 协议解析
4. 设备 ID 区分
5. 实时展示
6. 报文级查看
7. 单终端时序观察

### 当前不重点展开
1. 模型训练与推理
2. 复杂用户系统
3. 大规模部署
4. 产品级权限/账户体系
5. 复杂数据库架构
6. 过度追求高并发与完备运维

这个边界很重要，因为 Codex 需要知道：

> 这是一个**数据采集与展示原型**，不是完整商业平台。

---

## 四、项目中的核心对象

### 1. 终端设备
采集家庭电力量测数据，并通过 TCP 主动向后台上报。

### 2. 协议包
终端发送的原始数据单元，包含：
- 设备 ID
- 上报时间
- 三相电流
- 三相电压
- 三相有功功率

### 3. 后台接收软件
监听端口、接收连接、收包、解析、缓存、展示。

### 4. 设备视图
把协议包按设备聚合后形成的“设备级观察界面”。

### 5. 数据链路
终端 → TCP 连接 → 协议包 → 协议解析 → 设备数据视图 → 后续数据集构建

---

## 五、对 Codex 最重要的理解
Codex 在实现时需要明确：

### 1. 这个项目首先是“演示 + 原型”
要优先保证：
- 能收包
- 能解析
- 能看到数据
- 能按设备区分
- 能下钻到报文

### 2. 这个项目最终也会继续使用 WPF
因此当前实现不需要过度包袱，不必追求特别重的架构，但也不是一次性脚本。

更合适的理解是：
- 用 WPF 做一个能继续扩展的原型
- 保持结构清楚
- 不必为了“最终完美架构”拖慢当前交付

### 3. 真实收包是必须的
不能只做假数据大屏。

允许：
- 先用模拟数据辅助 UI 调试
但最终至少要：
- 真实监听 TCP 端口
- 接收协议包
- 解析并显示真实字段

### 4. 展示优先，但不能脱离真实链路
这个系统的价值在于：
- 展示感
- 工程真实性
两者都要有。

---

## 六、推荐给 Codex 的实现目标表述
可以这样告诉 Codex：

> 请实现一个 WPF 数据采集后台原型，用于本科毕业设计中的家庭电力量测数据接收与展示。该系统需要能够监听 TCP 端口、接收多个终端上报的协议包、按设备 ID 区分终端、解析协议字段，并提供三层界面：系统总览页、单终端详情页、协议包详情页。系统重点是“真实收包、实时展示、设备级观察、报文级下钻”，不需要复杂业务系统能力。

---

## 七、汇报时可以如何描述这个项目

### 一句话版本
这是一个面向家庭电力量测终端的数据接入与展示原型系统，用于验证从终端上报到后台解析展示的数据采集链路。

### 稍展开版本
本项目当前聚焦于毕业设计中的数据采集部分，目标是构建一个后台接收软件，能够通过 TCP 协议接收多个终端上报的电力量测数据，并完成协议解析、设备区分、实时展示和报文级查看，为后续数据集构建和系统整体实现提供基础。

---

## 八、Codex 不应误解的地方
1. 不是做通用 IM/Socket 调试器
2. 不是做复杂企业管理平台
3. 不是只做静态 UI
4. 不是只做假数据演示
5. 不是做 NILM 模型端
6. 不是做前端产品化大屏

它的核心是：
> **围绕真实终端协议的接收、解析、展示与观察。**
