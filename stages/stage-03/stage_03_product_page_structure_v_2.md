# Stage-03 家庭用电看板产品结构（V2）

- 文档日期：2026-05-07
- 关联文档：`STAGE03_HOME_APP_MVP_SPEC_V2.md`
- 本文定位：定义 Stage-03 面向用户应用的产品信息架构、页面职责、用户理解路径与前端呈现边界。
- 重要边界：计算、聚合、状态判断、事件配对、运行区间生成、kWh 统计、模型置信度处理均由运算后端负责。前端只消费后端提供的展示数据，并负责清晰、稳定、可信地呈现。

## 1. 产品定位

Stage-03 不再是模型验证界面，而是一个面向普通住户的家庭用电看板。

它的核心目标不是展示模型有多复杂，而是让用户快速理解：

1. 我家现在用电是否正常？
2. 现在哪些设备正在耗电？
3. 今天主要电量花在哪里？
4. 最近有没有明显的设备开关变化？
5. 如果数据不可靠或服务异常，用户能否看懂当前状态？

产品应优先建立用户信任，而不是优先堆叠图表和功能。

## 2. 目标用户与使用场景

### 2.1 普通住户

普通住户关心的是结果，而不是模型过程。

典型问题：

- 现在家里是不是有设备还在运行？
- 今天电量主要被哪些设备消耗了？
- 某个设备是不是刚刚启动或关闭过？
- 系统现在的数据是否可信？

### 2.2 演示者 / 管理员

演示者关心系统是否正常运行，以及当前数据来自真实接入还是模拟回放。

典型问题：

- 服务是否连接正常？
- 模型版本是什么？
- 模拟流是否正在运行？
- 当前数据是否延迟？

因此，普通用户页面和演示控制信息需要明确区分，避免把模型和系统细节暴露给普通用户主流程。

## 3. 产品设计原则

### 3.1 先给结论，再给细节

用户打开页面时，应先看到当前状态摘要，而不是先看到复杂曲线。

首页优先回答：

- 当前总功率
- 当前运行设备
- 当前耗电大户
- 今日用电摘要
- 最近事件

曲线、历史、运行区间属于解释层，不应压过首页摘要。

### 3.2 前端只呈现，不推断

前端不负责判断设备是否运行、不负责事件配对、不负责聚合电量、不负责解释模型输出。

前端只消费后端提供的 View Data，例如：

- 当前总功率
- 设备当前状态
- 设备当前功率
- 今日累计用电
- 最近事件
- 运行区间
- 服务状态
- 数据新鲜度状态

这样可以保证产品口径稳定，也便于后端替换模型或聚合逻辑。

### 3.3 明确展示可信度，而不是假装确定

NILM 本身存在估计误差。产品上不应给用户一种“绝对精确”的错觉。

推荐使用表达：

- 估计功率
- 估计用电量
- 可能运行中
- 数据延迟
- 服务断开
- 暂无足够数据

MVP 阶段可以不展示复杂置信度数值，但必须展示数据状态。

### 3.4 控制 MVP 范围

Stage-03 的第一目标是做出稳定、可理解、可演示的闭环。

优先做：

- 首页总览
- 设备详情
- 基础实时状态
- 系统状态

后置做：

- 完整历史分析
- 自定义时间范围
- 强建议/异常检测
- 复杂设备运行区间解释

## 4. 总体页面结构

推荐页面结构：

1. 首页总览 Dashboard
2. 设备详情 Device Detail
3. 实时用电 Realtime
4. 历史趋势 History
5. 系统状态 / 演示控制 System Status

其中：

- Dashboard 是用户入口，负责给出家庭用电摘要。
- Device Detail 是解释页，负责说明单个设备的状态、历史和事件。
- Realtime 是观察页，负责展示短时间窗口内的动态变化。
- History 是分析页，负责展示更长时间范围的用电结构。
- System Status 是演示者/管理员页，不应作为普通用户主流程的一部分。

## 5. 首页总览 Dashboard

### 5.1 页面目的

让用户打开应用后，在 5 秒内理解当前家庭用电状态。

它回答：

1. 当前总功率是多少？
2. 数据是否正常更新？
3. 哪些设备正在用电？
4. 当前主要耗电设备是谁？
5. 今天大概用了多少电？
6. 最近是否发生明显开关事件？

### 5.2 信息层级

首页应按“结论优先”的顺序组织：

1. 家庭当前状态摘要
2. 当前运行设备
3. 当前耗电 Top 3
4. 今日用电摘要
5. 最近事件
6. 建议/提醒占位

### 5.3 主要模块

#### 当前总功率卡片

展示：

- 当前估计总功率，单位 W
- 更新时间
- 数据状态：正常 / 数据延迟 / 服务断开 / 暂无数据

这是首页最高优先级模块。

#### 当前运行设备

展示正在运行或可能运行中的设备。

每个设备展示：

- 设备名称
- 当前估计功率
- 当前状态：运行中 / 关闭 / 未知
- 最近更新时间或最近事件

点击设备进入设备详情。

#### 当前耗电 Top 3

展示当前估计功率最高的三个设备。

展示：

- 设备名称
- 当前估计功率
- 当前占比

此模块用于帮助用户快速定位当前耗电大户。

#### 今日用电摘要

展示：

- 今日累计估计用电量，单位 kWh
- 今日主要设备用电占比

MVP 可以只展示今日总量和设备排行，不必做复杂同比/环比。

#### 最近事件摘要

展示最近 N 条设备 on/off 事件。

展示：

- 设备名称
- 事件类型
- 发生时间

点击事件进入对应设备详情，并定位到事件附近。

#### 提醒/建议占位

MVP 阶段不做强规则判断。

可展示：

- 暂无明显异常
- 建议功能建设中
- 当前数据不足，暂不生成建议

此模块只保留产品入口，不作为 P0 验收核心。

### 5.4 用户操作

- 点击设备进入设备详情
- 点击今日摘要进入历史趋势
- 点击事件进入设备详情
- 手动刷新当前状态

### 5.5 P0 验收标准

- 可以展示当前总功率
- 可以展示数据更新时间和数据状态
- 可以展示设备当前状态列表
- 可以展示当前耗电 Top 3
- 可以展示今日总估计用电量
- 可以展示最近事件
- 设备和事件可跳转到设备详情
- 服务异常或数据为空时有明确降级呈现

## 6. 设备详情 Device Detail

### 6.1 页面目的

围绕单个设备解释它当前是否在用电、今天用了多少电、最近何时开关过。

它回答：

1. 这个设备现在是否运行？
2. 当前估计功率是多少？
3. 今天大约耗了多少电？
4. 今天运行了多久？
5. 最近什么时候开启或关闭？

### 6.2 信息层级

1. 设备当前状态
2. 今日统计
3. 单设备功率曲线
4. 运行区间
5. 事件列表

### 6.3 主要模块

#### 设备状态摘要

展示：

- 设备名称
- 当前状态：运行中 / 关闭 / 未知
- 当前估计功率
- 最近更新时间
- 数据状态

#### 今日统计

展示：

- 今日累计估计用电量
- 今日累计运行时长
- 今日 on/off 事件次数

这些值全部由后端计算，前端不做推导。

#### 单设备功率曲线

默认展示今日曲线。

可切换：

- 最近 1 小时
- 今日
- 近 7 天

不同时间范围下的数据降采样由后端完成。

#### 运行区间列表

展示后端已经生成的运行区间。

字段：

- 开始时间
- 结束时间
- 持续时长
- 估计用电量

MVP 可以只展示最近若干条，不做复杂详情页。

#### 事件列表

展示最近 N 条事件。

字段：

- 事件类型
- 时间
- 来源：模型 / 规则 / 模拟 / 标注

MVP 可以隐藏来源字段，但数据结构中应保留。

### 6.4 用户操作

- 切换设备
- 切换时间范围
- 查看运行区间
- 返回来源页

### 6.5 进入上下文

设备详情应根据入口设置默认视图：

- 从首页设备卡片进入：默认今日
- 从实时页进入：默认最近 1 小时
- 从历史页进入：继承历史页时间范围
- 从事件进入：定位到事件附近时间窗口

### 6.6 P0 验收标准

- 可以展示设备当前状态
- 可以展示设备今日统计
- 可以展示设备功率曲线
- 可以展示最近事件
- 可以从首页跳转进入
- 不同数据状态有明确降级展示

## 7. 实时用电 Realtime

### 7.1 页面定位

Realtime 是观察页，不是首页替代品。

它适合用于：

- 展示最近几分钟家庭总功率变化
- 观察设备开关事件
- 演示在线模拟流
- 辅助确认模型输出是否稳定

对于普通用户，Realtime 可以作为次级页面；对于演示场景，它有较高价值。

### 7.2 主要模块

#### 实时总功率曲线

展示最近 5-15 分钟总功率变化。

前端只展示后端提供的时间序列，不负责窗口裁剪和插值。

#### 设备实时状态列表

每个设备展示：

- 当前状态
- 当前估计功率
- 最近事件

点击进入设备详情。

#### 单设备实时曲线

用户选择一个设备后，展示该设备最近一段时间的功率变化。

#### 最近事件流

按时间倒序展示事件。

支持按设备筛选，筛选逻辑可以由前端完成，也可以由后端查询支持。MVP 可先由前端筛选当前已加载事件。

#### 模拟控制区

只对演示者或管理员可见。

包括：

- 启动模拟
- 停止模拟
- 回放速度
- 当前数据源

普通用户模式下应隐藏或弱化。

### 7.3 优先级建议

Realtime 不必在 P0 做成完整独立页。

更稳妥的路径是：

- P0：Dashboard 中展示简化实时状态
- P1：补完整 Realtime 页面
- Demo 需要时：提前实现模拟控制区

## 8. 历史趋势 History

### 8.1 页面定位

History 是分析页，用于理解一段时间内的用电结构。

它回答：

1. 今天什么时候用电最多？
2. 哪些设备贡献了主要耗电？
3. 最近几天用电是否变高？

### 8.2 主要模块

#### 时间范围选择

MVP 推荐：

- 今日
- 近 7 天

自定义时间范围后置。

#### 总用电趋势图

展示后端提供的聚合结果。

- 今日：按小时聚合
- 近 7 天：按天聚合

前端不负责从原始采样点计算 kWh。

#### 设备用电占比

展示各设备估计用电量和占比。

推荐优先使用条形图，避免设备较多时饼图难以阅读。

点击设备进入设备详情，并继承当前时间范围。

#### 高峰时段

展示用电最高的几个时间段。

字段：

- 时间段
- 估计用电量
- 主要设备

MVP 可以后置。

### 8.3 优先级建议

History 放在 P1 是合理的。

但 Dashboard 依赖的今日用电摘要属于 P0 轻量聚合，应由后端提前提供。

因此聚合能力拆分为：

- P0：今日总量、今日设备排行、当前 Top 3
- P1：按小时、按天、近 7 天、高峰时段

## 9. 系统状态 / 演示控制 System Status

### 9.1 页面定位

该页面服务于演示者和管理员，不是普通住户的主流程页面。

它回答：

1. 服务是否可用？
2. 数据是否仍在更新？
3. 当前使用哪个模型版本？
4. 数据源是真实接入还是模拟回放？
5. 模拟流是否正在运行？

### 9.2 主要模块

#### 服务状态

展示：

- 服务连接状态
- 最近心跳时间
- 错误信息

#### 模型信息

展示：

- 模型版本
- 支持设备列表
- 输入采样周期
- 窗口大小

这些信息主要用于演示和诊断，普通用户不需要感知。

#### 数据源状态

展示：

- 当前数据模式：真实接入 / 模拟回放
- 最近数据时间
- 当前回放速度

#### 管理操作

可选操作：

- 启动模拟
- 停止模拟
- 刷新状态

### 9.3 命名建议

不建议在 MVP 中简单命名为 Settings。

更准确的名称：

- 系统状态
- Demo Control
- 服务状态
- 运行状态

如果未来要做真正的用户设置，再单独增加 Settings 页面。

## 10. 页面关系

```text
首页总览
  -> 当前运行设备 -> 设备详情（今日视图）
  -> 当前耗电 Top 3 -> 设备详情（今日视图）
  -> 今日用电摘要 -> 历史趋势（今日视图）
  -> 最近事件 -> 设备详情（事件附近窗口）

设备详情
  -> 切换设备 -> 设备详情
  -> 返回来源页

实时用电
  -> 设备状态卡片 -> 设备详情（最近 1 小时视图）
  -> 最近事件 -> 设备详情（事件附近窗口）

历史趋势
  -> 设备占比 -> 设备详情（继承历史时间范围）
  -> 高峰时段 -> 历史趋势筛选结果（后置）

系统状态
  -> 管理模拟流
  -> 查看模型和服务状态
```

## 11. 前端展示数据契约

本节只定义前端需要消费的展示语义，不定义计算过程。

### 11.1 Dashboard Summary

用于首页总览。

包含：

- 当前总功率
- 更新时间
- 数据状态
- 当前运行设备列表
- 当前耗电 Top 3
- 今日总估计用电量
- 今日设备用电排行
- 最近事件

### 11.2 Device Detail View

用于设备详情。

包含：

- 设备基础信息
- 当前状态
- 当前估计功率
- 今日统计
- 功率曲线数据
- 运行区间列表
- 事件列表

### 11.3 Realtime View

用于实时观察。

包含：

- 最近窗口内总功率序列
- 最近窗口内设备功率序列
- 当前设备状态列表
- 最近事件流
- 服务连接状态

### 11.4 History View

用于历史趋势。

包含：

- 时间范围
- 总用电聚合序列
- 设备用电聚合
- 高峰时段统计

### 11.5 System Status View

用于系统状态。

包含：

- 服务健康状态
- 最近心跳时间
- 模型信息
- 数据源状态
- 模拟流状态
- 错误信息

## 12. 状态与降级呈现

每个页面都必须考虑异常状态。

### 12.1 数据状态

推荐统一状态：

- 正常
- 数据延迟
- 服务断开
- 暂无数据
- 数据不足

### 12.2 设备状态

推荐统一状态：

- 运行中
- 关闭
- 未知

前端不判断状态，只展示后端结果。

### 12.3 降级策略

#### 服务断开

显示最后一次成功更新时间，并提示当前数据可能不是最新。

#### 暂无数据

显示空状态，不显示错误感强的页面。

#### 数据不足

曲线可以展示已有数据，同时提示统计结果可能暂不可用。

#### 单设备未知

该设备显示为未知，不影响其他设备展示。

## 13. MVP 优先级

### P0：可演示闭环

目标：让用户能看懂当前家庭用电状态，并能点进设备解释详情。

包含：

- 首页总览
- 设备详情
- 基础系统状态
- 当前状态展示
- 今日轻量摘要
- 最近事件
- 服务异常降级

### P1：增强理解

目标：让用户理解一段时间内的趋势。

包含：

- 实时用电完整页
- 历史趋势
- 按小时 / 按天聚合展示
- 设备用电占比
- 高峰时段

### P2：产品扩展

目标：增强用户留存和解释能力。

包含：

- 自定义时间范围
- 更丰富运行区间详情
- 提醒/建议
- 异常识别
- 用户自定义设备名称
- 多家庭 / 多站点

## 14. 第一版推荐交付范围

第一版建议控制在：

1. Dashboard
2. Device Detail
3. System Status

Realtime 可以先以首页中的简化实时状态形式存在，不必一开始做成完整独立页面。

History 可以后置，但 Dashboard 需要的今日摘要数据应提前由后端提供。

第一版成功标准不是功能多，而是：

- 数据流稳定
- 当前状态可信
- 页面关系清楚
- 用户能理解估计值的含义
- 服务异常时页面不崩、不误导
