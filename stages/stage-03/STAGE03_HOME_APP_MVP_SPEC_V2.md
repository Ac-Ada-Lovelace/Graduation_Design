# Stage-03 面向用户应用规格（MVP V2）

- 文档日期：2026-04-05
- 适用阶段：Stage-03（应用层主线）
- 关联说明：Stage-02 的离线/在线页面属于技术演示，不是主产品形态。

## 1. 产品定位

Stage-03 的主目标是做一个“普通用户可用”的家庭用电应用，而不是研发演示台。

一句话定位：
- 帮助用户快速看懂“现在谁在耗电、今天谁最耗电、是否存在异常运行”。

## 2. 目标与边界

### 2.1 核心目标

1. 用户在 10 秒内识别当前主要耗电设备。
2. 用户在 30 秒内理解当日用电结构与变化趋势。
3. 用户可查看设备级运行与事件记录，形成可执行的节能判断。

### 2.2 边界约束

1. Stage-03 不重复实现模型训练、数据采集协议解析。
2. Stage-03 只消费 Stage-02 产出的模型包能力与服务接口。
3. 对用户侧展示统一使用“估计值”口径，避免与电表真值混淆。

## 3. 目标用户与场景

### 3.1 目标用户

1. 家庭住户（非技术用户）
2. 简单运维角色（可选，负责启动/停止模拟或检查服务状态）

### 3.2 典型场景

1. 早晚高峰查看当前耗电大户。
2. 每天查看设备耗电占比与运行时长。
3. 回看最近事件，判断设备是否异常频繁启停。

## 4. 应用形态（MVP）

MVP 采用轻量 Web 应用，包含三类必做页面与一类概念保留能力。

### 4.1 必做功能

1. 实时总览（Realtime）
2. 历史分析（History）
3. 设备详情（Device Detail）

### 4.2 概念保留（先不做硬验收）

4. 提醒/建议（Advice）
   - 先保留入口和概念定义。
   - 不作为本轮强制交付项。
   - 后续根据真实运行数据再调整规则。

## 5. 页面与信息架构

建议导航：

1. 首页总览
2. 实时用电
3. 历史趋势
4. 设备详情
5. 设置（可后置）

### 5.1 首页总览

展示：

1. 当前总功率（W）
2. 当前前三耗电设备
3. 今日累计估计用电（kWh）
4. 最近事件摘要（on/off）

### 5.2 实时用电

展示：

1. 各设备当前估计功率卡片
2. 总功率实时曲线（短窗口）
3. 设备开关状态与最近更新时间

### 5.3 历史趋势

展示：

1. 今日/近 7 天设备耗电占比
2. 按小时用电趋势
3. 高峰时段标记

### 5.4 设备详情

展示：

1. 单设备功率曲线
2. 今日运行时长
3. 今日事件计数（on/off）
4. 最近 N 条事件时间

## 6. 数据口径（用户侧）

1. 功率单位：W
2. 电量单位：kWh（由功率积分估算）
3. 事件：on/off（基于模型后处理规则）
4. 时间：默认本地时区展示，后端存储 UTC
5. 所有指标默认注明“估计”

## 7. 系统对接方案

Stage-03 推荐采用 BFF（Backend for Frontend）方式接入 Stage-02：

1. 前端 -> Stage-03 BFF（鉴权、聚合、口径统一）
2. Stage-03 BFF -> Stage-02 Service（推理与状态接口）

MVP 依赖的下游接口：

1. `GET /health`
2. `GET /api/meta`
3. `GET /session/latest`
4. `GET /api/online/status`
5. `POST /api/online/start`（管理员能力，可选）
6. `POST /api/online/stop`（管理员能力，可选）

## 8. MVP 验收标准

### 8.1 必须通过（功能 1-3）

1. 用户可看到实时总功率与设备功率。
2. 用户可查看历史趋势与设备占比。
3. 用户可查看单设备运行信息与事件记录。
4. 页面刷新和切页不出现白屏或致命报错。

### 8.2 暂不强制（功能 4）

1. 提醒/建议模块仅保留概念和占位。
2. 不以提醒准确率作为本轮验收条件。

## 9. 实施顺序（建议）

1. 第一阶段：页面骨架 + 实时总览链路打通。
2. 第二阶段：历史趋势与设备详情完成。
3. 第三阶段：提醒/建议入口占位 + 文案框架。

## 10. 与 Stage-02 的关系

1. Stage-02：技术验证与演示（研发视角）。
2. Stage-03：用户应用（产品视角）。
3. Stage-03 复用 Stage-02 能力，不复刻 Stage-02 页面。
