# Stage-03 应用产品层计划（V1）

- 文档日期：2026-03-31
- 目标：将第二层认知能力转化为真实用户可用的 SaaS 后台能力。

---

## 1. 定位与边界

定位：
- Stage-03 是用户应用层，不重复实现采集与推理内核。

输入边界（仅消费）：
- `stage-02` 服务 API 与模型版本元数据。

不在 Stage-03 做的事：
- 模型训练细节
- 协议解析细节

---

## 2. MVP 功能范围

MVP 目标：做出“可登录、可看、可查、可追溯”的最小后台。

### 2.1 账号与权限

- 用户登录
- 基础角色（管理员/运营/只读）
- 页面级访问控制

### 2.2 资产与运行状态

- 站点列表
- 设备列表
- 当前在线状态
- 最近预测时间戳

### 2.3 认知结果展示

- 实时功率卡片（按电器）
- 事件列表（on/off）
- 近 24h 查询

### 2.4 版本追溯

- 当前模型版本展示
- 模型切换历史（先做只读）

---

## 3. 页面信息架构

建议菜单：

1. 总览（Dashboard）
2. 实时监控（Realtime）
3. 事件中心（Events）
4. 设备管理（Assets）
5. 模型治理（Model）
6. 系统管理（Users/Roles）

---

## 4. 对接 API（初版）

依赖第二层接口：

1. `GET /health`
2. `GET /api/meta`
3. `GET /session/latest`
4. `GET /api/online/status`
5. `POST /api/online/start`（管理员）
6. `POST /api/online/stop`（管理员）

应用层建议封装为 BFF（Backend for Frontend）：
- 前端不直接拼接底层接口，统一通过应用层后端转发和鉴权。

---

## 5. 数据模型（应用层自有）

建议最小表：

1. `users`
2. `roles`
3. `user_role_bindings`
4. `sites`
5. `devices`
6. `model_switch_logs`
7. `operation_audit_logs`

说明：
- 推理结果与事件可先不入库，仅做短期缓存 + 查询透传；
- 若后续做报表，再增加时序存储。

---

## 6. 验收标准（MVP）

功能验收：

1. 不同角色登录后菜单权限正确。
2. 可以查看实时预测功率与事件。
3. 可查看当前模型版本和最近更新信息。
4. 管理员可启动/停止在线模拟。

稳定性验收：

1. 连续运行 30 分钟页面无致命错误。
2. 接口错误有可读提示，不出现白屏。

---

## 7. 开发顺序（建议）

P0：
- 搭建应用层后端骨架 + 登录鉴权 + 接口代理

P1：
- 实时监控页 + 事件中心页

P2：
- 设备管理 + 模型治理页

P3：
- 操作审计 + 报表雏形
