# Stage-03 家庭用电看板 UI Spec（V1）

- 文档日期：2026-05-07
- 文档定位：纯 UI 规格说明
- 适用范围：Stage-03 面向住户的家庭用电看板前端界面
- 不包含内容：模型计算、kWh 聚合、设备状态判断、事件识别、运行区间生成、后端算法逻辑

## 1. UI 总目标

Stage-03 UI 的目标是让用户在尽量短的时间内理解家庭用电状态。

用户打开应用后，应能快速看到：

1. 当前家里大约用了多少电；
2. 哪些设备正在运行；
3. 当前主要耗电设备是谁；
4. 今天大约用了多少电；
5. 最近发生了哪些设备开关事件；
6. 系统数据是否可靠、是否延迟、是否断开。

UI 不强调技术感，不强调模型细节，而强调清晰、稳定、可信。

## 2. 页面范围

### 2.1 P0 页面

第一版 UI 包含 3 个页面：

1. 首页总览 Dashboard
2. 设备详情 Device Detail
3. 系统状态 / 演示控制 System Status

### 2.2 P1 页面

后续扩展页面：

1. 实时用电 Realtime
2. 历史趋势 History

### 2.3 推荐路由

```text
/dashboard
/device/:deviceId
/system-status
/realtime       # P1
/history        # P1
```

默认入口为 `/dashboard`。

## 3. 全局布局

### 3.1 桌面端布局

桌面端推荐使用左侧导航 + 主内容区。

```text
┌──────────────────────────────────────────────┐
│ App Shell                                    │
├──────────────┬───────────────────────────────┤
│ Sidebar      │ Main Content                  │
│              │                               │
│ Dashboard    │ Page Header                   │
│ Realtime     │ Cards / Charts / Lists        │
│ History      │                               │
│ System       │                               │
└──────────────┴───────────────────────────────┘
```

左侧导航宽度建议：220-260px。

主内容区最大宽度建议：1200-1440px。

主内容区应保留足够留白，避免像监控后台一样密集。

### 3.2 移动端布局

移动端推荐使用顶部标题 + 底部导航。

底部导航包含：

- 总览
- 实时
- 历史
- 系统

设备详情从卡片点击进入，不一定出现在底部导航中。

移动端页面应采用单列卡片流布局。

### 3.3 页面通用结构

每个页面遵循：

```text
Page Header
  - 页面标题
  - 页面说明 / 当前数据时间
  - 主要操作按钮

Content
  - 核心摘要
  - 图表 / 列表 / 详情
  - 辅助信息
```

## 4. 全局视觉原则

### 4.1 信息层级

视觉层级从高到低：

1. 当前总状态
2. 当前运行设备
3. 今日摘要
4. 曲线和趋势
5. 事件和细节
6. 系统诊断信息

首页不要一开始就堆满图表。用户第一眼应该看到结论。

### 4.2 语气与文案

推荐用语：

- 当前估计功率
- 今日估计用电量
- 可能运行中
- 数据延迟
- 服务断开
- 暂无数据
- 最近更新于

避免用语：

- 精确功率
- 确定耗电
- 异常设备
- 必须关闭
- 模型判断绝对正确

### 4.3 数值展示

功率单位：W。

电量单位：kWh。

时间展示：

- 刚刚
- 1 分钟前
- 10:42
- 今天 10:42
- 2026-05-07 10:42

数值推荐格式：

```text
1320 W
1.32 kW      # 大于 1000W 时可选
3.42 kWh
约 28 分钟
```

MVP 可以统一使用 W，避免 W/kW 自动切换带来理解成本。

### 4.4 状态色使用

状态色只用于表达状态，不用于装饰。

推荐语义：

- 正常：稳定、低刺激
- 运行中：突出但不过度警告
- 关闭：弱化
- 未知：中性
- 数据延迟：提醒
- 服务断开：明显错误

不要让所有高功率设备都显示成危险红色。高功率不等于异常。

## 5. 通用组件

### 5.1 App Shell

包含：

- 应用名称
- 导航入口
- 当前系统状态简标
- 主内容区

系统状态简标显示在侧边栏底部或页面右上角。

状态示例：

```text
● 数据正常
● 数据延迟
● 服务断开
```

### 5.2 Page Header

字段：

- 页面标题
- 简短说明
- 最近更新时间
- 操作按钮

Dashboard 示例：

```text
家庭用电总览
最近更新：10:42:18
[刷新]
```

Device Detail 示例：

```text
微波炉
当前状态：运行中 · 最近更新：10:42:18
[返回]
```

### 5.3 Status Badge

用于展示状态。

设备状态：

- 运行中
- 关闭
- 未知

数据状态：

- 正常
- 数据延迟
- 服务断开
- 暂无数据
- 数据不足

Badge 应短小，避免整句长文案。

### 5.4 Metric Card

用于展示单个关键指标。

结构：

```text
标题
主数值
辅助说明
状态 / 更新时间
```

示例：

```text
当前总功率
1320 W
约为当前家庭总用电
10:42:18 更新
```

### 5.5 Device Card

用于展示设备摘要。

字段：

- 设备名称
- 当前状态
- 当前估计功率
- 最近事件或更新时间

交互：

- 点击进入设备详情
- hover 时显示可点击反馈
- 键盘可聚焦

### 5.6 Event Item

用于展示设备事件。

字段：

- 设备名称
- 事件类型：开启 / 关闭
- 时间
- 来源标识，MVP 可隐藏

示例：

```text
微波炉 开启 · 10:38
电热水壶 关闭 · 10:31
```

### 5.7 Chart Card

图表外层统一使用 Chart Card。

包含：

- 图表标题
- 时间范围说明
- 图表主体
- 空状态 / 加载状态 / 错误状态

图表不要裸露在页面上，避免视觉散乱。

### 5.8 Empty State

空状态用于数据为空，不应显示成错误。

示例：

```text
暂无设备运行
当前没有识别到正在用电的设备。
```

```text
暂无事件
最近还没有明显的设备开关事件。
```

### 5.9 Error State

错误状态用于服务失败或数据不可用。

示例：

```text
服务暂时不可用
无法获取最新用电数据，请稍后刷新。
```

错误状态应提供刷新入口。

### 5.10 Skeleton / Loading

页面初次加载使用骨架屏。

不要在每个小组件里同时转圈，避免页面显得不稳定。

推荐：

- 页面级首次加载：骨架屏
- 局部刷新：保留旧数据，显示“正在更新”

## 6. Dashboard UI Spec

### 6.1 页面目标

首页用于让用户快速理解当前家庭用电状态。

首页不应成为复杂分析页，而应是摘要页。

### 6.2 页面结构

桌面端推荐布局：

```text
Page Header

Top Row
  ┌───────────────────────┬───────────────────────┐
  │ 当前总功率             │ 今日用电摘要           │
  └───────────────────────┴───────────────────────┘

Main Grid
  ┌───────────────────────┬───────────────────────┐
  │ 当前运行设备           │ 当前耗电 Top 3         │
  │                       │ 最近事件               │
  └───────────────────────┴───────────────────────┘

Bottom
  ┌───────────────────────────────────────────────┐
  │ 提醒 / 建议占位                               │
  └───────────────────────────────────────────────┘
```

移动端使用单列顺序：

1. 当前总功率
2. 今日用电摘要
3. 当前运行设备
4. 当前耗电 Top 3
5. 最近事件
6. 提醒/建议占位

### 6.3 当前总功率卡片

优先级最高。

展示内容：

- 标题：当前总功率
- 主数值：例如 `1320 W`
- 辅助说明：家庭当前估计总用电
- 更新时间
- 数据状态 Badge

状态表现：

- 正常：正常展示数值
- 数据延迟：保留最后数值，提示“数据延迟”
- 服务断开：保留最后数值或显示 `-- W`，提示“服务断开”
- 暂无数据：显示空状态

### 6.4 今日用电摘要卡片

展示内容：

- 今日估计用电量
- 主要设备排行，最多 3 个
- 可点击进入 History，P0 可以先不跳转

示例：

```text
今日估计用电量
3.42 kWh
主要来自：微波炉、电热水壶、冰箱
```

### 6.5 当前运行设备区域

展示正在运行或可能运行中的设备。

每个 Device Card 展示：

- 设备名称
- 状态 Badge
- 当前估计功率
- 最近更新时间

空状态：

```text
暂无设备运行
当前没有识别到正在用电的设备。
```

交互：

- 点击进入设备详情
- 卡片 hover 提示可点击

### 6.6 当前耗电 Top 3

展示当前功率最高的设备。

推荐使用简洁排行列表，不必使用复杂图表。

每行展示：

```text
1. 微波炉       820 W       62%
2. 电热水壶     350 W       26%
3. 冰箱         120 W        9%
```

如果设备不足 3 个，只展示已有设备。

### 6.7 最近事件

展示最近 5-8 条事件。

每条事件展示：

- 设备名称
- 开启 / 关闭
- 时间

点击事件进入设备详情，并定位到事件附近。

空状态：

```text
暂无最近事件
最近没有明显的设备开关变化。
```

### 6.8 提醒 / 建议占位

MVP 不做强建议。

展示方式应低调，不抢占主信息。

示例文案：

```text
暂无明显异常
建议功能仍在建设中，当前仅展示基础用电状态。
```

或：

```text
数据不足
当前数据量不足，暂不生成用电建议。
```

### 6.9 Dashboard 交互

- 点击设备卡片：进入 Device Detail
- 点击事件：进入 Device Detail，并带事件上下文
- 点击刷新：刷新当前页面数据
- 页面自动刷新：可选，建议 5-10 秒一次

自动刷新时不要让卡片明显闪烁。

## 7. Device Detail UI Spec

### 7.1 页面目标

设备详情用于解释单个设备的当前状态、今日表现和最近事件。

### 7.2 页面结构

桌面端推荐布局：

```text
Page Header

Top Row
  ┌───────────────────────┬───────────────────────┐
  │ 设备状态摘要           │ 今日统计               │
  └───────────────────────┴───────────────────────┘

Main
  ┌───────────────────────────────────────────────┐
  │ 单设备功率曲线                                 │
  └───────────────────────────────────────────────┘

Bottom Grid
  ┌───────────────────────┬───────────────────────┐
  │ 运行区间               │ 事件列表               │
  └───────────────────────┴───────────────────────┘
```

移动端使用单列：

1. 设备状态摘要
2. 今日统计
3. 功率曲线
4. 事件列表
5. 运行区间

### 7.3 设备状态摘要

展示内容：

- 设备名称
- 当前状态 Badge
- 当前估计功率
- 最近更新时间
- 数据状态

示例：

```text
微波炉
运行中
820 W
最近更新：10:42:18
```

未知状态示例：

```text
微波炉
未知
-- W
当前数据不足，无法判断设备状态。
```

### 7.4 今日统计

展示 3 个核心指标：

```text
今日估计用电量    0.84 kWh
今日运行时长      28 分钟
今日事件次数      6 次
```

可以使用 3 张小 Metric Card。

### 7.5 时间范围切换

设备曲线支持：

- 最近 1 小时
- 今日
- 近 7 天

默认规则：

- 从 Dashboard 进入：今日
- 从 Realtime 进入：最近 1 小时
- 从 History 进入：继承来源时间范围
- 从事件进入：事件附近窗口

UI 上使用 Segment Control。

示例：

```text
[最近 1 小时] [今日] [近 7 天]
```

### 7.6 单设备功率曲线

图表要求：

- X 轴：时间
- Y 轴：估计功率 W
- 鼠标 hover 显示具体时间和功率
- 数据不足时显示已有数据和提示
- 无数据时显示空状态

曲线不需要在 UI 中解释模型逻辑。

图表标题示例：

```text
功率变化
今日估计功率变化
```

### 7.7 运行区间列表

展示后端提供的运行区间。

字段：

- 开始时间
- 结束时间
- 持续时长
- 估计用电量

桌面端可使用表格。

移动端可使用卡片列表。

MVP 如果时间紧，可以隐藏运行区间，只保留事件列表。

### 7.8 事件列表

展示最近 N 条事件。

字段：

- 开启 / 关闭
- 时间
- 来源，MVP 可隐藏

示例：

```text
开启 · 10:38
关闭 · 10:41
开启 · 09:12
```

### 7.9 设备切换

设备详情页可以提供设备选择器。

形式：

- 桌面端：页面右上角 Select
- 移动端：标题下方 Select

如果 P0 时间紧，可以不做设备切换，只通过首页进入不同设备。

### 7.10 Device Detail 交互

- 返回上一页
- 切换时间范围
- 切换设备，P1
- 点击事件，曲线定位到事件附近，P1
- 刷新数据

## 8. System Status UI Spec

### 8.1 页面目标

系统状态页用于演示者和管理员确认系统是否正常运行。

它不是普通用户的核心页面。

### 8.2 页面结构

```text
Page Header

Status Grid
  ┌───────────────────────┬───────────────────────┐
  │ 服务状态               │ 数据源状态             │
  └───────────────────────┴───────────────────────┘

Info Grid
  ┌───────────────────────┬───────────────────────┐
  │ 模型信息               │ 模拟控制               │
  └───────────────────────┴───────────────────────┘

Error Panel
  ┌───────────────────────────────────────────────┐
  │ 最近错误 / 日志摘要                            │
  └───────────────────────────────────────────────┘
```

### 8.3 服务状态卡片

展示：

- 服务状态：正常 / 异常 / 未连接
- 最近心跳时间
- API 连接状态
- 错误摘要

### 8.4 数据源状态卡片

展示：

- 当前模式：真实接入 / 模拟回放
- 最近数据时间
- 当前回放速度
- 数据延迟状态

### 8.5 模型信息卡片

展示：

- 模型版本
- 支持设备列表
- 输入采样周期
- 窗口大小

这部分可以更技术化，因为目标用户是演示者/管理员。

### 8.6 模拟控制卡片

操作：

- 启动模拟
- 停止模拟
- 刷新状态

按钮状态：

- 模拟未运行：启动可用，停止禁用
- 模拟运行中：启动禁用，停止可用
- 服务断开：全部禁用

所有操作都需要明确反馈：

```text
模拟已启动
模拟已停止
启动失败，请检查服务状态
```

### 8.7 最近错误 / 日志摘要

展示最近错误信息。

MVP 可以只展示一条错误摘要。

不要做完整日志系统。

## 9. Realtime UI Spec（P1）

### 9.1 页面目标

实时页用于观察最近几分钟内家庭总功率和设备功率变化。

它偏观察和演示，不承担首页摘要职责。

### 9.2 页面结构

```text
Page Header

Main Chart
  ┌───────────────────────────────────────────────┐
  │ 实时总功率曲线                                 │
  └───────────────────────────────────────────────┘

Grid
  ┌───────────────────────┬───────────────────────┐
  │ 设备实时状态列表       │ 最近事件流             │
  └───────────────────────┴───────────────────────┘

Single Device Chart
  ┌───────────────────────────────────────────────┐
  │ 单设备实时曲线                                 │
  └───────────────────────────────────────────────┘
```

### 9.3 实时总功率曲线

展示最近 5-15 分钟。

要求：

- 曲线更新时不明显闪烁
- 保留旧数据直到新数据到达
- 数据延迟时显示提示
- 服务断开时停止更新并显示状态

### 9.4 设备实时状态列表

每个设备展示：

- 名称
- 当前状态
- 当前估计功率
- 最近事件

点击设备后，下面的单设备曲线切换到该设备。

### 9.5 最近事件流

展示最近事件。

支持设备筛选，P1 可做。

### 9.6 单设备实时曲线

用户选择设备后显示。

默认选择当前功率最高设备，或第一个运行中设备。

## 10. History UI Spec（P1）

### 10.1 页面目标

历史页用于理解一段时间内的用电结构和趋势。

### 10.2 页面结构

```text
Page Header

Controls
  [今日] [近 7 天] [自定义]
  [全部设备 / 设备选择]

Main Chart
  ┌───────────────────────────────────────────────┐
  │ 总用电趋势图                                   │
  └───────────────────────────────────────────────┘

Grid
  ┌───────────────────────┬───────────────────────┐
  │ 设备用电排行           │ 高峰时段               │
  └───────────────────────┴───────────────────────┘
```

### 10.3 时间范围选择

MVP/P1 推荐：

- 今日
- 近 7 天

自定义后置。

### 10.4 总用电趋势图

今日视图：按小时展示。

近 7 天视图：按天展示。

单位：kWh。

### 10.5 设备用电排行

推荐条形图或排行列表。

不推荐优先使用饼图，因为设备多时可读性差。

每项展示：

- 设备名称
- 估计用电量
- 占比

点击设备进入设备详情，并继承当前时间范围。

### 10.6 高峰时段

展示用电量最高的几个时间段。

字段：

- 时间段
- 估计用电量
- 主要设备

MVP 可以后置。

## 11. 图表规范

### 11.1 通用要求

所有图表都必须有：

- 标题
- 单位
- 时间范围说明
- 空状态
- 加载状态
- 错误状态

### 11.2 功率曲线

用于 Realtime 和 Device Detail。

- Y 轴单位：W
- X 轴单位：时间
- hover 展示时间和功率
- 数据点过多时由后端或数据层提供降采样结果

### 11.3 用电趋势图

用于 History。

- Y 轴单位：kWh
- X 轴：小时或日期
- 今日按小时
- 近 7 天按天

### 11.4 占比图

优先使用条形图或排行列表。

饼图仅在设备数量较少时使用。

### 11.5 图表空状态

示例：

```text
暂无足够数据
当前时间范围内没有可展示的功率数据。
```

## 12. 交互规范

### 12.1 刷新

Dashboard 支持手动刷新。

实时页支持自动刷新。

刷新时：

- 保留当前旧数据
- 显示轻量更新状态
- 不要整体清空页面

### 12.2 跳转

设备相关入口统一跳转到 Device Detail。

入口上下文影响默认时间范围。

### 12.3 Hover

桌面端可点击卡片应有 hover 状态。

移动端不依赖 hover 表达关键信息。

### 12.4 Click Target

移动端点击区域高度建议不小于 44px。

设备卡片整体可点击，不只文字可点击。

### 12.5 Toast

用于反馈短操作结果。

适用：

- 刷新成功
- 刷新失败
- 模拟启动成功
- 模拟停止成功

不要用 Toast 承载关键长期状态。

关键状态应显示在页面内。

## 13. 响应式规范

### 13.1 桌面端

宽度大于 1024px：

- 使用侧边栏
- 内容区支持双列卡片
- 图表可横向展开

### 13.2 平板端

宽度 768-1024px：

- 侧边栏可收起
- 内容区使用单列或窄双列

### 13.3 移动端

宽度小于 768px：

- 使用底部导航
- 所有卡片单列排列
- 图表高度适当降低
- 表格改为卡片列表

## 14. 可访问性要求

P0 至少满足：

- 所有可点击元素可键盘访问
- 状态不能只靠颜色表达
- 图表需要有文字摘要
- 表单控件有明确 label
- 错误信息可读、可理解

状态 Badge 应同时有颜色和文字。

例如不要只显示红点，应显示：

```text
服务断开
```

## 15. 文案规范

### 15.1 数据正常

```text
数据正常

```

### 15.2 数据延迟

```text
数据延迟

```

```text
服务断开
无法获取最新用电数据，请检查服务状态。
```

### 15.4 暂无设备运行


```text
暂无最近事件
```

```text
当前数据量不足，暂时无法展示该统计结果。
```

## 16. P0 页面验收清单

### Dashboard

- 页面有明确标题和更新时间
- 当前总功率可展示
- 数据状态可展示
- 当前运行设备可展示
- 当前耗电 Top 3 可展示
- 今日用电摘要可展示
- 最近事件可展示
- 空状态可展示
- 服务断开状态可展示
- 设备卡片可进入设备详情

### Device Detail

- 设备名称可展示
- 当前状态可展示
- 当前估计功率可展示
- 今日统计可展示
- 功率曲线可展示
- 最近事件可展示
- 返回入口可用
- 时间范围切换可用，至少支持今日

- 最近心跳时间可展示
- 模型信息可展示
- 数据源状态可展示
- 模拟状态可展示
- 刷新按钮可用
- 模拟启动/停止按钮状态正确
- 错误信息可展示

## 18. 非目标

本 UI Spec 不解决：

- 模型如何识别设备
- 如何计算运行状态
- 如何聚合 kWh
- 如何生成运行区间
- 如何判断异常
- 如何定义设备置信度
- 后端 API 具体实现
- 数据库结构

这些应由后端计算文档或 View Contract 文档定义。

## 19. 总结

Stage-03 UI 的重点不是复杂，而是可信。

第一版应优先保证：

1. 用户能一眼看懂当前用电状态；
2. 用户能点进设备理解原因；
3. 演示者能确认服务和模拟流状态；
4. 数据为空、延迟、断开时页面不误导用户；
5. 前端不承担任何推断和计算逻辑。

当这条主路径稳定后，再扩展 Realtime 和 History 页面。
