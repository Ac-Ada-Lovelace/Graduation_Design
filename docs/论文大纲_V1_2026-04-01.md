## 第2章 需求分析与总体架构（重点细化）

### 2.1 场景与需求

1. 场景对象：终端设备、采集后台、推理服务、业务用户。
2. 功能需求：采集、解析、推理、评估、展示、追溯。
3. 非功能需求：稳定性、可追溯、可维护、可扩展。

### 2.2 三层架构定义

1. 第一层：数据采集基建层（职责、输入、输出、非目标）。
2. 第二层：认知与运行基建层（职责、输入、输出、非目标）。
3. 第三层：应用产品层（职责与边界，当前保留）。

### 2.3 层间接口与边界冻结

1. 第一层到第二层的数据字段规范与质量门禁。
2. 第二层内部模型包契约：`nilm_model_interface_v1`。
3. 第二层到第三层的 API 消费边界（结果消费，不耦合训练细节）。

### 2.4 总体数据流与时序

1. 离线链路时序：区间推理、指标计算、报告输出。
2. 在线链路时序：回放喂数、滚动推理、状态轮询。
3. 发布链路时序：候选包、验收、激活、回滚。

### 2.5 关键设计原则

1. 契约优先。
2. 低耦合替换。
3. 指标可复现。
4. 版本可追溯。

### 2.6 本章小结

1. 明确论文后续章节将按两层落地、一层保留的方式展开。
