# 项目文档（V1）

- 日期：2026-04-01
- 项目：Graduation_Design
- 定位：面向家庭能耗场景的三层式 NILM 系统

## 1. 项目目标

构建“采集基建 -> 认知基建 -> 应用产品”的完整路径：

1. 稳定接入并记录真实电力数据。
2. 将 NILM 模型工程化为可部署、可评估、可回滚的能力。
3. 在应用层承载面向用户的 SaaS 后台能力。

## 2. 三层架构

### 2.1 第一层：数据采集基建层（已实现）

职责：

1. TCP 接入与多终端管理。
2. 协议解析（44 字节固定结构）。
3. 设备状态与实时观测。
4. JSONL 落盘留痕。

目录：

- `stages/stage-01-data-collection`

### 2.2 第二层：认知与运行基建层（已实现主干）

职责：

1. 模型训练、导出、工件契约。
2. 推理服务 API。
3. 回放联调与端到端演示。
4. 指标验收与模型切换回滚。

目录：

- `stages/stage-02`

说明：

- 当前 `stage-02/ui` 是工程验证控制台，不是最终用户应用。

### 2.3 第三层：应用产品层（规划中）

职责：

1. 多用户与权限管理。
2. 资产与设备管理。
3. 实时监控、事件中心、报表分析。
4. 模型版本追溯与运营支撑。

目录：

- `stages/stage-03`

## 3. 层间接口

### 3.1 第一层 -> 第二层

标准时序字段（最小）：

1. `timestamp_utc`
2. `mains_w`
3. `kettle_w` / `microwave_w` / `toaster_w`（可空）

### 3.2 第二层模型包契约

接口版本：

- `nilm_model_interface_v1`

部署包关键文件：

1. `model.onnx`
2. `model_meta.json`
3. `normalization.json`
4. `postprocess.json`
5. `interface_spec.json`
6. `package_manifest.json`

### 3.3 第二层 -> 第三层

应用侧消费接口（核心）：

1. `GET /health`
2. `GET /api/meta`
3. `POST /api/offline/infer`
4. `POST /api/online/start`
5. `POST /api/online/stop`
6. `GET /api/online/status`
7. `GET /session/latest`

## 4. 当前进展

1. 第一层：可演示、可收包、可解析、可留痕。
2. 第二层：可运行闭环、可离线评估、可在线模拟、可回滚。
3. 第三层：已形成 MVP 规划文档，待进入实现。
