# 引用格式审查与补入方案 V1

建立日期：2026-05-10

适用对象：前三章正文稿 V2.1 之后的引用补入工作。

主要依据：`附件4：毕业设计撰写规范和相关表格/9 毕业设计（论文）的撰写规范及要求.doc`。

## 1. 附件四中的直接要求

附件四“5．参考文献”部分对引用和参考文献提出了以下要求：

- 论文引用的文献应以近期发表的、与毕业设计工作直接有关的文献为主。
- 参考文献是论文中引用文献出处的目录表。
- 凡引用本人或他人已公开或未公开发表文献中的学术思想、观点、研究方法、设计方案等，不论是借鉴、评论、综述，还是作为立论依据或学术发展基础，都应编入参考文献目录。
- 直接引用文字应直录原文并使用引号。
- 直接引用和间接引用都不应断章取义。
- 参考文献著录方法采用 `GB7714-2005《文后参考文献著录规则》` 中规定的“顺序编码制”。
- 参考文献采用中外文混编。
- 正文引用出处按引用先后顺序，用阿拉伯数字和方括号 `[ ]` 标注。
- 正文引用号放在引文结束处最后一个字的右上角，作为对参考文献表相应条目的呼应。
- 文后参考文献表中，各条文献按论文中的文献序号顺序排列。

## 2. 本论文执行口径

### 2.1 标准版本

虽然目前国家标准已有更新版本，但本次论文格式执行应优先服从附件四。因此，本阶段按附件四写明的 `GB7714-2005` 顺序编码制处理参考文献。

如后续学院或指导教师明确要求使用更新版 GB/T 7714，再整体调整文后著录格式。

### 2.2 正文引用标注

正式 DOCX 中应使用上标方括号编号，例如：

```text
非侵入式负荷监测最早由 Hart 提出，其核心思想是在总入口侧采集总负荷信息并推断设备级用电状态[1]。
```

其中 `[1]` 在 DOCX 中应设置为上标。

Markdown 工作稿中可暂用普通 `[1]` 作为可检查标记，但生成 DOCX 时必须统一转为上标。

### 2.3 编号规则

- 按正文首次引用顺序连续编号。
- 同一文献再次引用时沿用首次编号。
- 不沿用开题报告或引用库中的原始编号。
- 不把候选引用库的 `R01`、`R02` 等编号写入正文。
- 文后参考文献表只列正文实际引用过的文献。

### 2.4 引用内容边界

- 对 NILM 起源、研究现状、方法分类、公开数据集、工程部署挑战等外部知识，应给出引用。
- 对本系统实际完成的采集程序、推理服务、接口结构、页面和测试结果，应以本项目证据支撑，不能用外部文献替代。
- 如果直接引用原文，必须使用引号；当前论文尽量采用转述和概括，减少直接引文。
- 不引用与论文论断关系弱、仅为背景浏览的网页材料，除非确实用于工程背景说明。

## 3. 文后参考文献表规则

### 3.1 排列方式

- 文后参考文献表按正文中首次出现的序号排列。
- 中外文文献混合排列，不再按中文、英文分组。
- 每条文献只出现一次。

### 3.2 常用条目格式

期刊：

```text
[1] 作者. 题名[J]. 刊名, 年份, 卷(期): 起止页码.
```

会议：

```text
[2] 作者. 题名[C]//会议名. 出版地: 出版者, 年份: 起止页码.
```

学位论文：

```text
[3] 作者. 题名[D]. 保存地: 保存单位, 年份.
```

标准：

```text
[4] 责任者. 标准题名: 标准编号[S]. 出版地: 出版者, 年份.
```

电子文献：

```text
[5] 作者或机构. 题名[EB/OL]. (发表或更新日期)[引用日期]. 获取和访问路径.
```

## 4. 前三章补引用策略

### 4.1 必须覆盖的位置

| 章节 | 引用目的 | 建议数量 |
|---|---|---:|
| 1.1 研究背景与意义 | 支撑 NILM 概念、低侵入优势和系统工程价值 | 2-3 |
| 1.2 国内外研究现状 | 支撑 NILM 起源、传统方法、概率模型、深度学习、数据集和部署研究 | 6-8 |
| 2.1 非侵入式负荷监测技术概述 | 支撑定义、任务分类、负荷特征、事件检测和评价指标 | 3-5 |
| 2.2 系统关键技术 | 支撑推理服务、数据记录、接口设计或模型部署 | 2-4 |
| 3.6 技术经济与可行性分析 | 支撑低侵入式部署优势、工程可行性和真实部署挑战 | 2-3 |

### 4.2 不宜引用的位置

- 摘要不标注引用。
- 主要工作、章节组织结构、小结中一般不密集放引用。
- 图表标题中一般不放引用，除非图表改编自外部资料。
- 只有项目确实采用的技术，才引用对应官方文档，例如 ONNX、ONNX Runtime、FastAPI、JSON Lines。

## 5. 推荐执行步骤

1. 从 `reference_library_v1.md` 中选出前三章实际使用的 12-15 篇。
2. 对入选文献做元数据核验，尤其是作者、题名、期刊或会议、年份、卷期、页码、DOI/URL。
3. 生成“前三章引用分配表”，明确每篇文献第一次出现在哪个句子或段落。
4. 在 Markdown 正文中插入普通方括号编号，便于检查顺序。
5. 按正文首次出现顺序生成参考文献表。
6. 导出 DOCX。
7. 在 DOCX 中将正文引用编号统一设置为上标。
8. 检查 DOCX 中引用编号、参考文献条目、字号、行距和分页。

## 6. 当前结论

附件四已经明确要求正文引用编号采用右上角上标形式，并按 `GB7714-2005` 顺序编码制著录。后续补引用时，应以附件四为最高格式依据；此前根据格式骨架或审阅报告形成的普通方括号方案只能作为 Markdown 工作稿的临时检查形式，不能作为最终 DOCX 格式。
