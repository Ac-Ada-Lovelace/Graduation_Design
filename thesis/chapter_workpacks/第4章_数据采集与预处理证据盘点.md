## 5. 第 4 章建议大纲

### 4.1 本章目标与模块边界

说明本章围绕数据采集层展开，目标是完成终端接入、协议解析、数据聚合、文件留痕和推理前数据整理。明确本章不讨论 NILM 模型结构、推理指标和应用层展示。

### 4.2 数据采集模块总体流程

建议配图：`图 4-1 数据采集与预处理流程图`

流程建议：

1. 量测终端或模拟终端建立 TCP 连接。
2. 采集服务按 44 字节读取完整报文。
3. 协议解析器按字段偏移解析设备 ID、上报时间、电流、电压和功率。
4. 视图模型按设备 ID 聚合实时状态。
5. JSONL 存储模块追加写入结构化记录。
6. 后续推理服务读取结构化数据或实时记录作为输入。

### 4.3 TCP 采集服务设计与实现

应写内容：

- 使用 `TcpListener` 按配置地址和端口监听。
- 每个客户端连接进入独立异步处理流程。
- 通过固定长度缓冲区读取 44 字节完整报文。
- 连接关闭但不足 44 字节时记录为残缺报文。
- 网络异常转换为传输异常记录，避免程序整体崩溃。

关键证据：

- `TcpMeasurementServer.StartAsync`
- `TcpMeasurementServer.AcceptLoopAsync`
- `TcpMeasurementServer.HandleClientAsync`
- `TcpMeasurementServer.ReadFrameAsync`

### 4.4 量测报文协议解析

建议配表：`表 4-1 量测上报报文字段结构`

字段结构：

| 偏移 | 长度 | 类型 | 字段 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | 4 | Int32 | 设备 ID | 用于区分终端 |
| 4 | 4 | Int32 | 上报时间 | Unix 时间戳 |
| 8 | 4 | Float32 | 电流 A | A 相电流 |
| 12 | 4 | Float32 | 电流 B | B 相电流 |
| 16 | 4 | Float32 | 电流 C | C 相电流 |
| 20 | 4 | Float32 | 电压 A | A 相电压 |
| 24 | 4 | Float32 | 电压 B | B 相电压 |
| 28 | 4 | Float32 | 电压 C | C 相电压 |
| 32 | 4 | Float32 | 功率 A | A 相功率 |
| 36 | 4 | Float32 | 功率 B | B 相功率 |
| 40 | 4 | Float32 | 功率 C | C 相功率 |

应写边界：

- 代码实现采用 little-endian 读取。
- 当前实现解析的是定长二进制报文，不是文本协议。
- 字段级解析结果会保留偏移、长度、原始十六进制和解析值，便于后续报文详情页展示。

### 4.5 设备状态聚合与异常状态处理

应写内容：

- 成功报文按设备 ID 进入设备聚合。
- 配置文件中的设备名称用于把设备 ID 映射为可读名称。
- 最新报文列表保留最近 200 条。
- 异常报文计入异常统计。
- `PartialFrame`、`ParseError`、`TransportError`、`StorageError` 可作为异常类型说明。

注意：

当前“离线超时”在配置与视图模型中已有设计痕迹，写作时应谨慎表述为“依据离线超时参数维护在线状态”，不要夸大为完整故障诊断能力。

### 4.6 数据落盘与 JSONL 记录结构

建议配表：`表 4-2 JSONL 数据记录字段`

可写字段：

| 字段 | 含义 |
| --- | --- |
| `receivedAt` | 平台接收时间 |
| `remoteEndPoint` | TCP 来源连接 |
| `deviceId` | 设备编号 |
| `deviceName` | 设备名称 |
| `reportTimeUtc` | 终端上报时间 |
| `currentA/currentB/currentC` | 三相电流 |
| `voltageA/voltageB/voltageC` | 三相电压 |
| `powerA/powerB/powerC` | 三相功率 |
| `parseStatus` | 解析状态 |
| `errorMessage` | 异常说明 |
| `rawHex` | 原始报文十六进制 |

建议正文强调：

- JSONL 适合追加写入和后续逐行读取。
- 单条记录同时保留原始报文和解析后的结构化字段。
- 本阶段不引入数据库，降低毕业设计原型的工程复杂度。

### 4.7 模拟终端与联调方法

应写内容：

- 模拟终端从后台配置中读取监听端口与设备名称。
- 设备 ID 可通过显式列表或范围配置。
- 默认启用 `1-20` 设备范围。
- 每个终端按发送间隔生成一条 44 字节二进制报文。
- 连接失败或中断后按重连间隔自动重试。

这节可作为“测试与验证方法”的前置说明，但完整测试结果仍放第 7 章。

### 4.8 本章小结

小结建议收束为：

本章完成数据从终端接入到结构化记录生成的链路说明，为后续 NILM 推理服务提供数据输入基础；本章不评价模型识别效果，模型相关内容在第 5 章展开。
