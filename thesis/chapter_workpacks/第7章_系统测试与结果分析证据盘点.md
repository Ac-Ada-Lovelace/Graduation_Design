## 3. 第7章建议结构

### 7.1 测试环境与数据说明

写明本机验证环境、Stage-02 venv、ONNX Runtime CPU 推理、模型包、CSV 数据来源和数据时间范围。

关键数据：

- 数据集时间范围：`2013-03-17T19:12:50Z` 至 `2013-03-24T19:12:43Z`。
- train-ready 行数：532616。
- 目标设备：kettle、microwave、toaster。
- 主模型包：event optimized。
- 对照/回滚模型包：error optimized。

### 7.2 数据采集模块测试

引用第 4 章已有证据，重点做测试口径归纳：

- 常规多设备联调：20 个模拟终端、成功解析记录 300 条、停止时连接异常记录 20 条。
- 接收端压力联调：80 个模拟连接、20 秒、15920 条报文发送和接收成功、Success=15920。
- 说明该压力联调为本机模拟条件，不等同于真实跨网络长期运行。

### 7.3 推理服务功能测试

覆盖三个命令：

```powershell
python integration\manage_package_registry.py verify-active
python integration\run_service_api_checks.py
python integration\run_demo_smoke.py --data-csv model\data\processed\house_1_1s_kmt\timeseries_1s_train_ready.csv --speed 200 --max-rows 320
```

可写结论：

- active package 成功解析到模型包 zip。
- API 检查通过 session、offline 和 online 链路。
- 在线 smoke 在 320 行回放后得到 `ready=True`、`pred_count=20`。

### 7.4 模型识别与误差指标分析

主表建议引用固定区间验收报告：

| 模型包 | MAE 平均值/W | RMSE 平均值/W | Event F1 平均值 |
| --- | ---: | ---: | ---: |
| event optimized | 11.2317 | 44.7314 | 1.0000 |
| error optimized | 12.9034 | 62.7407 | 0.8333 |

分析方向：

- event optimized 在事件 F1 上更适合作为演示主包。
- error optimized 可作为回滚包，但当前验收区间上的 Event F1 较低。
- 误差指标应结合设备启停瞬间和高功率短时事件讨论，不宜只看平均值。

### 7.5 在线回放与端到端测试

引用 `smoke.txt` 和 `online-status-summary.json`：

- smoke 回放 320 行，窗口长度 301，因此最终可形成 20 次预测。
- 服务端在线回放样例发送 420 行，形成 120 次预测。
- `history.true_w` 和 `history.pred_w` 均按三个设备返回 120 个点。

### 7.6 测试结果讨论

建议讨论：

1. 数据采集模块在本机模拟条件下具备接收、解析和落盘能力。
2. 推理服务在 CPU 环境下能够加载 GPU 训练机导出的 ONNX 模型包。
3. 模型包契约、manifest 校验和注册表切换提高了模型替换可控性。
4. 局限：当前验证主要基于公开数据集和本机回放，尚未覆盖真实家庭硬件长期在线运行。
5. 局限：短时高功率设备事件可能造成 MaxAbsDiff 较大，需要结合事件时刻和平均误差共同判断。
